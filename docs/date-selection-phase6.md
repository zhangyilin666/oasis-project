# 日期筛选第六批交付

## 范围与产品行为

已新增日期筛选域、页面和独立记录仓库。规则版本 `date-selection-v1`，传统表版本 `lunar-typescript-1.8.6-sect1`，复用已有 `almanac-v1`，不新增运行依赖。

输入为计划名称、事项（嫁娶／出行／入宅／开市）、首尾包含的 1–31 天窗口、可用星期、明确排除日和场地／人员备注。支持 1900-01-01 至 2099-12-31，固定 UTC+08:00，不套用设备时区或历史夏令时。姓名、生日、个人命盘不是输入。

两种模式：

- 仅按现实条件：星期及排除日决定候选，传统条目仍保留供查看。
- 同时核对宜忌：现实条件通过后，事项还须明确列于宜、且未列于忌。仅列忌、宜忌并列为冲突；宜忌均未列出为未涵盖。

四条日志逐日保留：可用星期、排除日期、传统事项、场地与人员安排。最后一项始终为未涵盖、待人工确认；不会把非空备注当成实际核验。只有启用规则影响候选，但所有规则、原始宜／忌列表和查表月干支均可展开查看。现实冲突优先保留，不能被传统“宜”覆盖。

候选按日期排序，不提供分数或最佳日期排名；有候选也不表示已确认场地、人事、冲煞、个人八字或时辰。日历中的“无”“诸事不宜”“余事勿取／馀事勿取”等概括条目保留原文，不扩展成四类事项的已验证规则。用户可筛出候选查看，保存及导出仍包含全部日期。

H5 的事项使用原生 select，起止日期允许键盘输入 `YYYY-MM-DD`，域层核验实际日期；其他端保留原生 picker。小屏使用逐日卡片、规则展开及单列日期输入。修改任一输入后立即失效旧预览，要求重新筛选；已保存快照保留原样。

2. 同页明确 `sect=1` 自交节当日起算月，`sect=2` 才按交节时刻。现有黄历使用 `getDayYi(1)`／`getDayJi(1)`，本版原样复用整日口径：交节当日 00:00 换查表月；中午仅是历法事实采样时刻。日干支 00:00 换日。这与六爻按精确交节时刻取月建的口径不同，没有混用。
3. [lunar-typescript 官方仓库](https://github.com/6tail/lunar-typescript)作为依赖实现及 MIT 许可入口。前端版本仍锁定 1.8.6。

## 快照与存储

独立键 `oasis.date-selection.records.v1`，信封 `schemaVersion: 1`、`kind: date-selection`；最多 20 条，复用共享 snapshot-store。每条包含规范化输入、完整每日事实、四条规则、启用标志、判定理由、汇总、来源、约定及版本。保存时深拷贝，回看和导出不重新查询历法引擎。

读取会核验支持版本、合法日期与顺序、星期、干支形式、条目上限、完整日期数量、规则日志与汇总的内部一致性及来源／约定版本。校验使用保存的传统事实重建 v1 日志，不静默重算历史表。它是格式和内部一致性校验，不是加密签名，也不能证明手工改写后的传统事实仍与上游原表相同。

未知版本、损坏 JSON、重复记录 ID、记录数量异常会阻止读取、覆盖保存、删除和导出并保留原始值。达到 20 条上限会明确报错，不自动挤掉旧记录。写入权限或容量失败显示未确认保存成功。清除本机应用数据会删除记录，导出提供 JSON 自主备份。
