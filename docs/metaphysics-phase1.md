## 固定的计算规则

输入为公历日期、准确到分钟的当地钟表时间、当时的 UTC 偏移与传统排盘性别参数。偏移支持 −12 至 +14 小时，每 15 分钟一步；必须由用户包含出生当年的夏令时。本版不查询 IANA 历史时区，不接受未知时间以中午替代。有效出生日期自 1900 年起，拒绝未来瞬间和转换后越界日期。

- 中文盘先将同一瞬间换算到北京时间 UTC+8；这是本版明确的固定排盘约定，不是全球出生地当地时辰的等价替代，也不是真太阳时。
- 八字固定 `lunar-typescript@1.8.6`，年按立春、月按节气；日柱 `sect=2`，晚子时日柱仍算当日，时柱沿用上游规则；起运 `sect=1`。
- 紫微固定 `iztro@2.6.1`，农历正月初一换年、晚子归当日、闰月前十五日归本月/后半归下月、默认四化与亮度表。大限年龄为虚岁。每次重设标量配置；若其他模块注入自定义四化/亮度表则拒绝生成冒称默认规则的盘面。
- 西方盘固定 `astronomy-engine@2.1.19`，UTC 瞬间、地心、当日真黄道、热带黄道分区；使用 `GeoVector → Ecliptic`。太阳/行星启用光行差，月亮使用该库月球模型。顺逆行按前后一小时黄经变化估算，近驻留阈值每日 0.001°；五类相位统一容许度 6°，页面可见。
- 各系统计算失败时独立返回错误，不回退到模拟命盘。资料编辑后清除旧结果；迟到的旧计算不能覆盖新输入。

五行数量只统计四柱八个字，不代表旺衰或补益需求。紫微五行局、八字五行、西方星座分类不互相换算。天文和历法事实的计算检查不等于现实预测有效性认证。

## 代码与扩展边界

```text
src/domain/metaphysics/
  types.ts       可序列化的 BirthProfile / ChartResult / ExplorationResult（schemaVersion=1）
  time.ts        输入验证、UTC 瞬间与北京时间归一化
  catalog.ts     能力状态与锁定引擎来源，无计算依赖
  bazi.ts        八字适配器
  ziwei.ts       紫微适配器；隔离上游全局配置使用
  western.ts     天文坐标、星座划分与相位适配器
  index.ts       懒加载各适配器、独立失败处理、主题对照
src/pages/explore/index.vue
                 出生输入、五术目录、三盘切换、主题对照与依据
```

首页只新增入口；计算库随排盘动作按需加载，不由首页直接导入。新增直接依赖固定精确版本，传递依赖锁在 `package-lock.json`。第三方版权及完整 MIT 文本随 `src/static/licenses/metaphysics.txt` 打包，涵盖三库及所用传递依赖；更换版本后运行 `node scripts/generate-metaphysics-notices.mjs` 更新。

新增 API、数据库迁移和常驻服务均非本阶段所需。旧 `frontend/` 原生微信小程序代码未增加新入口；本阶段的微信产物来自 `oasis-uniapp` 的微信构建。

## 验证

测试命令在 `oasis-uniapp` 执行。最终 `npm test` **48 项通过**（39 项新命盘测试、9 项既有测试），`npm run typecheck`、`npm run build:h5`、`npm run build:mp-weixin` 均通过。构建仅出现已有 Sass legacy JS API 弃用提示。

- 固定八字期望来自已安装 `lunar-python@1.4.8`，覆盖 8 组立春、午夜、闰日及闰月样例。两个库共享 6tail 系谱，此项是前后端回归对照，不是独立历法认证。
- 紫微使用[作者公开示例](https://docs.iztro.com/quick-start)的固定命宫、身宫、星曜等验证接入。
- 西方太阳黄经对照 [USNO 2024 年二分二至时刻](https://aa.usno.navy.mil/calculated/seasons?dst=true&submit=Get+Data&tz=5&tz_label=true&tz_sign=-1&year=2024)，容差 0.03°；日月相位对照[香港天文台 2024 年历](https://www.hko.gov.hk/tc/gts/astron2024/files/HKO_almanac_2024.pdf)的 3 月满月，容差 0.1°。这是部分独立天文参考，未验证十天体全时域精度。
- 自动检查非法输入、同一瞬间的不同 UTC 表达、三个设备时区、单引擎故障隔离，确保不编造结果。
- 补测紫微全局自定义四化污染后的拒绝生成，以及同日早子/晚子的紫微一致性和八字时柱差异。
- 浏览器在 390px / 320px 下实际填写并计算，验证空表单错误、三盘生成与切换、目录状态、规则与来源展开，以及修改资料后旧结果清空；没有横向溢出，浏览器未报告警告或错误。
- 后端审查时运行已有历法、手机流程、报告完整性相关测试，94 项通过（临时 SQLite、mock AI）。后端未修改；本机实际 FastAPI/Pydantic 等版本高于 requirements，不能将其写成部署锁版本验收。

微信构建最初被原有 `v-input-label` 指令阻塞。对八字表单及账号恢复表单添加平台编译分支：H5/App 保留原有输入标签指令，微信采用原生 `aria-label` 输入；微信不注册该指令。修复后两种构建与类型检查均重新通过。微信构建目录总文件体积约 1.76 MB（仅本地文件统计，不代表平台上传验收）。

本期未发布公网，未调用付费 AI，未进行实体 iPhone/Android 或微信开发者工具真机验收。
