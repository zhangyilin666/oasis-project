# 基础命盘、历法与文化板块接入分析

调研日期：2026-10-03。本文覆盖十八板块清单中的十项：八字、紫微、黄历节气、择日、姓名文化、修习、节气养生文化、堪舆空间、相学文化、塔罗。其他八项见同目录易卦、三式和占星专题。这里的优先级、最小范围和验收要求是项目设计判断，不是来源机构对本软件的背书。

## 研究方法与证据边界

先核对本项目的适配器、目录、一期及二期交付记录，再阅读作者 API、官方历法资料、数字化古籍底本、公共机构说明。检索中文及英文资料，侧重规则、输入、实现和授权。未进行预测有效性研究、医学内容系统综述或全流派校勘。古籍记述、确定性程序结果、现代可验证事实分别登记。

在线来源可证明某个 API 或文献段落存在，不能证明候选实现所有边界正确。公开可读的网页、照片或译文不自动获得随软件再分发的授权；本轮只引用链接并自行概括，不批量导入正文和牌图。

## 1. 四柱八字

**已有事实：** 前端 `lunar-typescript@1.8.6` 已生成四柱、十神、藏干、五行数量和大运；后端 `lunar-python` 的 AI 报告独立存在。当前两端不能仅凭同名库就当成完全相同的流派实现。`lunar` 作者列出了干支、节气、八字等 API，并明确说明部分资料来自网络整理与作者理解。[作者总览](https://6tail.cn/calendar/overview.html)、[API 目录](https://6tail.cn/calendar/api.html)

**输入与下一步：** 延用已确认出生时刻、历史时区、性别参数；增加规则档案后再提供晚子换日、起运算法对照，以及按节气切换的流年／流月。原始民用时、UTC、北京时间、可选太阳时必须分别保留，不在表单里覆盖生日。

**解释层：** 格局、旺衰、喜用神、神煞有不同取法；须先写成带文献定位的规则卡和可展示的推导链，再考虑提供选定规则的分析。八字字面五行数量不直接转换为“缺什么就补什么”。

**验收：** 立春前后、交节分钟、23:00／00:00、闰日、境外跨日、夏令时；每个可切换规则需一组能产生差异的固定样例。回归现有八字报告事实核对，不把新体系输出交给旧核对器冒充已验。

**优先级判断：** 流年流月和规则对照在第二批；全自动喜用神／格局结论在文献与解释契约完成后。作者现声明 `lunar` 以修错为主，推荐新增功能使用 Tyme；现有锁定版本继续保留，迁移另做前后端金标准比较，不能为追新版本直接换库。[维护声明](https://6tail.cn/calendar/overview.html)、[Tyme 文档](https://6tail.cn/tyme.html)

## 2. 紫微斗数

**已有事实：** 已接本命盘与指定日期大限、流年、流月。上游支持 `yearDivide`、`horoscopeDivide`、`ageDivide`、`dayDivide`、`algorithm` 等设置；作者同时明确配置会污染后续全局调用。[iztro 配置](https://docs.iztro.com/posts/config-n-plugin)、[运限 API](https://docs.iztro.com/en_US/posts/horoscope)

**下一步：** 先做流派预设的并排核对，再开放小限、流日、流时。预设必须包含年界、日界、闰月、安星法、四化与亮度版本，不能只有“某派”一个标签。自化、飞化、三方四正等解释，应回指具体宫位／星曜事实。

**输入与输出：** 出生资料不变；流日流时另需明确观察瞬间，不能继续只用日期隐含中午。输出各层宫位、四化、流曜、所用时间边界和适配器版本。

**验收：** 两个不同预设交替调用不串配置；春节与立春分界分别验证；闰月 15／16 日、早晚子、童限、超出大限支持区间。来源中的“可配置”不等于任意配置都已做独立盘面核验。

**优先级判断：** 属于已有基础上的第二批扩展；先保持一期／二期固定规则稳定。

## 3. 黄历与二十四节气

**区分两类资料：** 公农历转换、太阳黄经与交节时刻是历法／天文资料；宜忌、值神等是特定传统规则。香港天文台说明节气以黄经每 15° 划分，其发布交节时间采用 UTC+8。[节气定义](https://www.hko.gov.hk/sc/gts/time/24solarterms.htm)、[交节时间资料](https://www.hko.gov.hk/sc/gts/astronomy/Solar_Term.htm)

**已有与可接范围：** 首页已有当日黄历。下一步可加任意日期浏览、前后节气、交节时刻与来源；避免在当年固定月日硬编码节气。展示“农历某月”与“节令月”两个概念。单日宜忌沿用上游既定规则并显示其来源，不称统一择吉标准。

**输入：** 日期、查看时区；准确交节需时刻。**验收：** 香港天文台逐年公农历对照、分钟级交节资料、闰月、日界与跨年；不要用只精确到日的表验证秒级输出。

**优先级判断：** 第二批，可复用已有历法库；数据覆盖范围以本项目已验收区间为准，而非照抄上游宽泛年份支持声明。

## 4. 择日

**研究结论：** 不是“黄历里有宜嫁娶，就已完成择日”。至少分日期事实、通书规则筛选、个人／地点约束三层。软件先允许用户指定事项、候选日期区间及现实不可用日，列出每条规则的通过／冲突原因。

**候选资料：** `lunar` 已列每日／时辰宜忌、旬空、值神等接口，可作来源明确的规则素材；《钦定协纪辨方书》可作为后续古籍核对入口，本次只确认卷三索引，未完成全书规则校勘。[时辰 API](https://6tail.cn/calendar/lunar-time.html)、[古籍卷三索引](https://ctext.org/wiki.pl?chapter=459211&if=gb&remap=gb)

**需先固定：** 用事类别、年／月界、冲煞参照对象、时辰口径、神煞取舍、规则优先顺序。不同流派相冲突时并列显示理由；日历、场地和人的可用时间应保留为独立现实条件。

**最小范围与验收：** 先做有限日期窗口的规则筛选和筛选日志，不输出保证成功的日期。每条规则附正／反例，缺规则或输入时明确无法判断，禁止空白默认“吉”。上游文档不是每条传统数据来源的完整证明，需继续核对底本。

**优先级判断：** 第三批；先建规则卡与测试，再接个体化择日。

## 5. 姓名文化

**可验证的数据基础：** Unicode Unihan 给出读音、字形、变体、笔画等资料，`kTotalStrokes` 为 informative 属性，另有来源相关笔画差异。它不定义一个字的命理五行或人格分数。[Unihan UAX #38](https://unicode.org/reports/tr38/)

**最小范围：** 用户输入姓名／候选名；提供字形与读音确认、典籍出处、自写释义、笔画来源、同音与显示兼容性，并允许自记寓意。先做好多音字、复姓、繁简一对多、生僻字和字体回退。

**需分开的规则：** 现代笔画、字书笔画、特定姓名术的笔画口径不能混成一个数字。五格、数理、字义五行等若后续提供，应作为指定体系的文化规则展示，单独建版本、引用及例子。没有确认的原典及统计证据，不标“改名提升运势”。

**数据和验收：** 使用前固定 Unicode 数据版本及对应许可；现代字典完整释义、字体、拼音数据另核权利。测试扩展区字符、异体字、多音字、空格／连接符和人工读音确认。

**优先级判断：** 第三批文化工具；不把它接入生日自动评分。

## 6. 山：静心、经典与修习记录

**资料定位：** 《坐忘论》可作思想／文本学习来源，不能把古籍中的修炼效能原样改写为健康保证。[数字化原文](https://zh.wikisource.org/wiki/坐忘論)

**最小范围：** 有出处的原创导读、自选计时、暂停／结束、练习记录和个人反思。输入仅主题、时长和笔记；不需要生日。不同修习传统分别介绍，不把所有练习并成一个“能量值”。

**健康表述边界：** NCCIH 对冥想研究的效果与局限分项说明，并建议不要用冥想取代常规医疗；因此产品定位为自愿的日常记录，不自动给高强度呼吸、禁食、长时间闭关或疾病治疗方案。[NCCIH 说明](https://www.nccih.nih.gov/health/meditation-and-mindfulness-effectiveness-and-safety)

**验收：** 暂停不累计、后台／锁屏后计时合理、用户随时结束、存储失败不丢旧记录，典籍版本及原创说明分开。内容审核与计时器正确性分别验收。

**优先级判断：** 第二批可先上记录工具与少量校订内容。

## 7. 医：节气与养生文化

**资料分层：** 中医概念、历史文本、现代健康知识分别标注。国家卫健委 2024 年健康素养资料是现代基础健康教育候选；其公开内容不支持从命盘推断疾病或处方。[官方通知](https://www.nhc.gov.cn/xcs/c100123/202405/73a4927142f34152abed875634a3c13b.shtml)、[官方 PDF](https://www.nhc.gov.cn/xcs/c100123/202404/c30d31cb877749ce94ce23d2c55ad973/files/1733220375579_91723.pdf)

**最小范围：** 节气历法卡、来源明确的传统文化词条、现代公共健康资料链接及自选作息笔记。先不采集症状、病历或生物特征；紫微疾厄宫、八字五行不能触发诊断、药物或补益推荐。

**地区差异：** 节气季候描述有历史与地理背景，不能将中原季候原封不动应用于南半球或所有气候区。[香港天文台的节气与季候说明](https://www.hko.gov.hk/sc/gts/time/24solarterms.htm)

**验收与缺口：** 每张内容卡需作者／机构、发布日期、文献位置、复核日期；健康建议需独立编辑审核。当前未导入内容，也未完成医学审核，不能把候选资料收集写成已上线养生库。

**优先级判断：** 第二批先上资料入口与文化卡，健康建议经审核后分批。

## 8. 相：堪舆与空间

**事实层：** 先收户型、比例、朝向测量值、测量日期、真北／磁北、采光和通风观察；传统解释另设图层。NOAA 明确磁偏角随时间及位置变化，磁罗盘读数不能直接当作真北。[NOAA 磁偏角](https://www.ngdc.noaa.gov/geomag/declination.shtml)

**流派拆分：** 形势、八宅、玄空等应分开立规格；八宅需确认宅向／坐向与人命卦规则，玄空还需建造／启用／改建时期、山向和运盘规则。上述是待核对输入清单，不代表已裁定各派争议。《阳宅十书》数字化页存在 OCR 初稿提示，本轮未凭其识别文本写排盘规则。[古籍候选入口](https://ctext.org/wiki.pl?chapter=412426&if=gb)

**最小范围与验收：** 手动空间档案和方位标注，保存原始测量与误差，不从照片猜准确朝向。0°／360°、顺时针方向、真磁北转换来源、户型缩放、边界方位、测量不确定性均要覆盖。传感器和定位如将来启用，再在实际使用时说明用途。

**优先级判断：** 第二批空间事实档案；第三批选择一种传统盘法。无需为了档案功能先引入排盘库。

## 9. 相学文化

**文献问题：** 《太清神鉴》四库提要本身讨论旧题作者不可信；因此内容库应保留版本、题署与编者意见，不把旧题作者当已确定事实。[《太清神鉴》提要](https://zh.wikisource.org/zh-hans/太清神鑑_(四庫全書本))

**最小范围：** 历史术语、原创图解与文献阅读；用户选择词条，不上传个体面部／手部照片作人格、健康、能力、命运推断。面部检测 API 的关键点准确率不是相学断语的有效性证据。

**验收：** 图解标注出处和图像许可，历史偏见语句作为历史材料说明，不转成评判现实个体的评分。当前没有核验可供商业再分发的完整校勘语料，先进行词条编辑。

**优先级判断：** 第三批文化内容，不建立自动识人接口。

## 10. 塔罗

**资料结论：** V&A 对其馆藏的说明涵盖标准 78 张牌及历史牌组差异；卡牌名称、编号和图像体系不总能互换。[V&A 馆藏说明](https://www.vam.ac.uk/articles/tarot-cards)

**最小范围：** 先选定一套牌目，做用户手动录入的牌阵、正逆位、问题与自己的复盘。输入含牌组版本、位置、牌 ID、朝向和抽取方法；生日不是必填。

**后续随机抽取：** 固定无放回抽取、是否含正逆位、洗牌方法与保存规则；刷新不能重新抽取。密码学随机数是可采用的工程选项，不据此宣称抽牌有现实预测能力。未启用随机模式时不显示假洗牌过程。

**授权与验收：** 不直接抓取现代牌图、牌义或 V&A 馆藏照片；优先自制文字牌面，图像另核权利。牌目唯一、无重复、正逆位留存、牌阵位置、旧记录重开不变以及存储错误均需测试。

**优先级判断：** 第二批可先做文本记录，图像与解释随后独立接入。
