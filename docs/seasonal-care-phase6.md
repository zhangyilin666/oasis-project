# 节气与养生文化第六批交付

## 已完成的最小范围

新增 `seasonal-care` 域、页面、独立记录仓库及专项测试。规则版本 `seasonal-care-v1`，内容版本 `seasonal-care-content-v1`。复用 `almanac-v1` 与现有 `lunar-typescript@1.8.6`，没有新增运行依赖。

页面支持公历日期、全部／四时文化／饮食／活动／作息五个主题。日期范围为 1900–2099 年，采用固定 UTC+08:00 当天 12:00 的实际节气区间；不跟随设备时区，不套历史夏令时。四季目录分别自立春、立夏、立秋、立冬开始，每季六个节气，属于阅读目录的组织方式，不推定用户所在地的气象季节。

默认“全部”显示当前文化季节的一张古籍导读，以及全年通用的三张公共健康卡。传统文化、现代公共健康资料在页面上分为两个区域；选择单主题时另一区明确提示无对应卡，不补造内容。

七张短卡均为自写摘要或评论：

| 卡片 | 内容范围 | 是否随文化季节切换 |
| --- | --- | --- |
| 春·发陈 | 古代文本中的萌发与舒展意象 | 是 |
| 夏·蕃秀 | 古代文本中的繁茂与生长意象 | 是 |
| 秋·容平 | 古代文本中的收敛与安宁意象 | 是 |
| 冬·闭藏 | 古代文本中的闭藏意象 | 是 |
| 日常饮食 | WHO 所列充足、平衡、适量、多样原则 | 否 |
| 日常活动 | WHO 对通勤、家务、休闲身体活动的范围说明 | 否 |
| 作息记录 | CDC 关于规律作息、年龄差异与睡眠质量的概述 | 否 |

每张卡保留原机构或文献、标题、文本定位、页面日期或固定修订号、复核日期与链接。不会显示药物、补剂、食疗方、器官对应诊断、疗效承诺，也不会由生日或五行匹配健康建议。文化卡中的观察问题是产品原创提示，与文献中的历史观点分开理解。公共健康卡全年保持相同内容，不改写成节气处方。

## 实际核对的来源

本版复核日期：2026-10-03。

- [《黄帝内经·素问》第一卷，固定修订 2083230](https://zh.wikisource.org/w/index.php?title=黃帝內經/素問第一卷&oldid=2083230)：读到“ 四气调神大论篇第二 ”四段起首的发陈、蕃秀、容平、闭藏；页面固定修订日期为 2021-10-17。古代汇编不硬署单一作者，不给出未经校勘的成书公历日期。仅保留四个短词及原创导读，不复制整段文本，也不采用其病因、疗效或睡眠时长说法作为现代建议。
- [WHO Healthy diet](https://www.who.int/news-room/fact-sheets/detail/healthy-diet)：页面日期 2026-01-26，定位 Overview 的四个基本原则。摘要不包含个体饮食处方、补充剂建议或人口统计数字。
- [WHO Physical activity](https://www.who.int/news-room/fact-sheets/detail/physical-activity)：页面日期 2024-06-26，定位 Overview 与 How much physical activity is recommended。采用活动范围与“有活动优于完全不动”的一般说明；没有给所有用户统一运动负荷。
- [CDC About Sleep](https://www.cdc.gov/sleep/about/index.html)：页面日期 2024-05-15，定位 Key points、What to do、Sleep quality。采用规律作息与睡眠质量的一般摘要，没有按古代时辰、命盘或年龄猜测用户睡眠需求。
- [香港天文台二十四节气](https://www.hko.gov.hk/sc/gts/time/24solarterms.htm)：历法卡的定义与文化背景来源。说明部分节气名反映古代中原气候，故 UI 明确地区与南北半球差异。交节实际计算仍为锁定历法库，香港天文台不为本软件整个日期范围背书。
- [日本国立天文台 2026 历要](https://eco.mtk.nao.ac.jp/koyomi/yoko/2026/rekiyou262.html)：独立四立交节分钟资料。2026 立夏、立秋、立冬均晚于所选当日中午，测试确保不会在整个交节日一开始就提前换文化目录。
- [香港天文台 2025 公农历表](https://www.hko.gov.hk/tc/gts/time/calendar/text/files/T2025c.txt)：独立春节样例，2025-01-29 为正月初一且仍属立春之前的冬季文化目录。

原候选国家卫健委 2024 健康素养 HTML 本次访问返回 412，PDF 超时，因此没有把未成功读到的内容纳入卡片，也不声称已核实其全文。官方公开链接、摘要和数据来源不意味着第三方页面配图或长文获得再分发许可；本版没有引入图片或长文。

## 自选习惯记录

用户手填记录主题／习惯（100 字）、状态（只作观察／计划尝试／已经做过）、当地观察（1000 字）与个人作息笔记（2000 字）。不采集出生资料、症状量表或病历，不自动计算健康分、达标与连续完成天数。

日期／主题变更立即失效旧阅读结果；个人笔记编辑保留已经查到的资料，并允许另存新快照。已保存记录回看原样卡片与历法事实；不会在打开时重新查询网络或重新计算。H5 使用可键盘操作的日期文本与原生主题 select，其他端保留 picker；日期格式与实际闰日均在域层验证。

本机键 `oasis.seasonal-care.records.v1`，`schemaVersion: 1`，`kind: seasonal-care`，最多 50 条。记录包含完整 reading（查询输入、历法事实、卡片、来源、约定与版本）和 personal。沿用共享 snapshot-store 的序列化、容量、唯一 ID、读写异常与损坏保护。

校验确认：已支持版本、卡片与源元数据的当前版本内容、日期、UTC8 中午、节气名称及相邻关系、前后时刻包围观察时刻、四时归属、字段限额及规范化文本。校验不重新计算天文事实；这属于格式与内部一致性校验，不是对历史计算结果的加密签名。

未知版本、损坏 JSON、来源或卡片文本改动、重复 ID 等会阻止写入、删除和导出，同时保留原始值。第 51 条拒绝保存而不清除旧记录；写入失败显示未确认成功。支持删除确认、完整 JSON 导出和存储读取重试。

- 50 份全部笔记字段达上限的完整快照，重复保存时间的 ID 唯一性与第 51 条无覆盖。

`npm run typecheck`：通过。总体 H5 构建、目录路由、真实浏览器交互和小屏验收交由集成流程，本文件不将尚未获得的结果写成通过。

后续内容新增必须保留来源日期和文本定位，并分开审核文化事实与现代健康表述。本批未完成医学指南系统综述、所有传统医籍的校勘或面向特定疾病的编辑审核，不能扩称个人健康方案。
