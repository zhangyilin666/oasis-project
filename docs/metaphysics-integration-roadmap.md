# 十八个板块的调研结论与逐步接入路线

调研日期：2026-10-03。依据用户要求，先分析整个已提出的范围，再从条件成熟的模块开始接入。范围来自当前五术目录的十三项，加上此前路线提到的七政四余、印度占星、太乙、择日与姓名文化五项，共十八项；不是声称覆盖世界上所有术数。西方占星和塔罗保留跨文化体系身份，五术分类在软件中用于组织导航。

本文件保留研究阶段的总路线与能力基线。[一期](metaphysics-phase1.md)、[二期](metaphysics-phase2.md)、[第三批](metaphysics-phase3.md)保留历史交付状态；最新范围及实际验证见[集成验收](metaphysics-phase9.md)，逐模块状态见[持续交付清单](metaphysics-delivery-ledger.md)。

十八板块目前均已接入各自注明范围的计算、内容或记录页面，主题同读支持19类独立档案。后续细分流派、未经核验的四余/断法、设备实测和生产发布不据此视为完成。下方矩阵保留研究开始时的基线，不能用“未实现”栏推断当前状态。

## 结论：保留共享资料，各体系独立计算

开发依次接入 **梅花年月日时起卦** 与 **西方指定日期行运快照**，再扩展六爻纳甲、规则对照、黄历及细分运限。奇门、大六壬、太乙、七政和印度占星均在注明盘法、底本及独立参考后开放最小子体系；原计划中的范围选择和资料缺口见下文，最新验收见交付清单。

“能算天体／干支”“符合所选传统排盘规则”“解释有文献来源”“能预测现实结果”是四件不同的事。前三项分别验收，不能借计算精度声明第四项。跨体系融通先做共同资料、主题并列和可追溯解释，不做各体系投票的命运分数。

## 会影响实现的发现

1. **经典数字化文本还要校核。** 梅花时间法能找到直接算例；六爻某些网络整页混入现代增订、录入错字及不一致表例，不能整页复制成规则库。需要把原典、现代整理、自写推导分开。详情见易卦专题。
2. **同一个库名不等于同一版本。** 三式候选的 PyPI 发布和作者主干有版本差异，部分测试只检查输出结构或局部规则。选库应固定提交／发布版本，并核对完整盘面，不以仓库自称“金标准”为验收。
3. **授权必须按实际复用对象核对。** 部分奇门候选只有 README 的许可说法，另一些候选可读独立 LICENSE；图库、古籍校注、外部数据、天文引擎及封装库需要分别登记。Swiss Ephemeris 的当前专业合同需重新按官方版本评估，本轮继续使用现有 MIT 天文引擎。详情见三式／占星专题；这不构成对某种部署方式的法律结论。
4. **上游维护路线已变化。** lunar 作者说明后续以修错为主并推荐 Tyme；项目暂不迁移，因为现有历法结果和边界已经固定测试，换库需要独立对照。[作者维护说明](https://6tail.cn/calendar/overview.html)
5. **空间、姓名与健康不能由生日补齐。** 真北／磁北是测量基准，字库笔画是语言数据，健康知识是另一条证据链。把它们强行换算成同一种五行权重，会抹去来源与必要输入。[NOAA](https://www.ngdc.noaa.gov/geomag/declination.shtml)、[Unihan](https://unicode.org/reports/tr38/)、[国家卫健委资料](https://www.nhc.gov.cn/xcs/c100123/202405/73a4927142f34152abed875634a3c13b.shtml)

## 第一批接入规格

### 梅花年月日时法

使用用户明确填写的问事日期、钟表时间与 UTC 偏移，先得到 UTC，再换算固定北京时间。按农历年支序、月数、日数及问事时支序计算；保存农历展开、两层和数及余数。闰月是否取同名月数、23 点日界、互卦和体用口径都写入规则说明，不能说是各流派唯一规则。

旧六爻／两数记录维持 `divination-v1` 的重算语义，新时间法使用独立方法和规则版本；读取时检查两者对应关系，不能用新版算法无提示重写旧记录。公历日期、UTC、转换后北京时间越界时直接报错。

### 西方行运快照

复用三盘中的可选观察日期，明确计算 **该日北京时间 12:00，即 UTC 04:00** 的十天体位置与相对于出生盘十天体的相位。称“指定时刻快照”，不称当天所有行运；不求整日命中窗口、未来事件、行运宫位或出生四轴相位。

行运对本命保留方向，包含同名天体；合、六合、刑、拱、冲统一采用 1° 软件容许度，与已有本命盘 6° 规则分别说明。未填观察日期不增加计算。结果保留观察 UTC 和规则说明，随完整快照保存；旧快照继续直接展示，不重新计算。

## 通用接入合同

每个计算器保留：原始输入、时间／历法归一、`method`、`ruleVersion`、引擎及版本、事实、计算步骤、引用、限制与生成时刻。出生、问事、空间、练习、牌阵是不同记录类型；不把所有输入扩展成一个到处带生日的对象。

每个新模块按以下顺序落地：

1. 指定底本／盘法、实际许可和支持范围，写出例外与未定规则。
2. 收集能独立复核的普通盘及边界盘，记录来源和精度；库自己算出的结果只能作回归，不能充当独立证据。
3. 实现无 UI 的确定性计算与输入验证；失败明确报错。
4. 接入页面、字段说明、局部错误、记录／导出；旧版本存档要么原样查看，要么显式选规则重算。
5. 验证数值、页面交互、H5／小程序构建，并写明实机与部署状态。

研究尚未覆盖全部流派，也没有安装或运行所有候选库。可以完成“十八项都分析”，但不能据此写成“十八项都可用”。本轮核验细节、访问失败、未导入的语料及候选测试缺口均保留在四份专题中。
