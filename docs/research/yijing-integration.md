# 易卦接入调研：六爻纳甲与梅花扩展

调研日期：2026-10-03。范围：现有 `oasis-uniapp/src/domain/divination/` 的后续接入。本文只规定研究结论与实施边界，不表示这些能力已经交付。

## 1. 结论与顺序

**梅花年月日时起卦可以先实施。** 现有六十四卦、动爻、变卦、互卦和体用结构可复用，项目已锁定 `lunar-typescript@1.8.6`，古籍中有两组完整算例，香港天文台有可独立验证的现代农历日期。需要先把闰月、换年、换日和时区写成可保存的规则约定。

**六爻先补装卦事实，再补日期事实，最后考虑解释层。** 推荐拆为：

1. 纳甲干支、八宫归属、世应、六亲、变爻六亲、缺亲伏神。与实际日期无关，可穷举验证。
2. 问事时间口径、节气月建、日辰、六神、旬空。时区、23:00 与节气交接必须有边界测试。
3. 用户手动选用神、结构性生克说明。旺衰、应期与自动断事需另立流派规格和案例集，不随装卦一并宣称完成。

近期不必引入完整 Python 占卜服务，也不需为了少量确定性规则扩大前端运行时。三个 Python 候选库适合作为参考与差分工具；它们的测试与交叉验证不等于现实预测效力。现有手动六爻和两数法应继续使用原规则，不能被新法重新解释。

## 3. 梅花时间法的可实施规格

### 3.1 原文明确的部分

《梅花易数》卷一“年月日时起例”采用年支序数、月数、日数、时支序数；“观梅占”“牡丹占”提供完整的加数、上下卦和动爻结果。先天卦数为乾 1、兑 2、离 3、震 4、巽 5、坎 6、艮 7、坤 8。见[卷一原文](https://zh.wikisource.org/zh-hans/梅花易數/卷一)。

令 `Y` 为子 1 至亥 12 的年支序数，`M` 为农历月数，`D` 为农历日，`H` 为子 1 至亥 12 的时支序数：

```text
upperSum = Y + M + D
total = upperSum + H
上卦序数 = upperSum % 8；余 0 取 8
下卦序数 = total % 8；余 0 取 8
动爻 = total % 6；余 0 取 6
```

余 0 取第六爻作为统一边界规则保存；不把公元年份、年干序数、月建地支或小时数直接代入。现有体用规则仍是唯一动爻所处经卦为用，另一经卦为体。互卦继续保留现有“结构互卦，乾坤亦取自身”的软件约定；卷一还载“乾坤无互，互其变卦”的另一规则，当前不静默切换。

### 3.2 原文未统一规定的部分：本项目建议

本次查阅的卷一没有明确闰月、现代时区、夏令时、国际日期变更或早晚子换日办法。以下是本项目可复现的工程选择，不写成“古法唯一标准”：

| 参数 | 首版建议 | 必须显示/留存 |
|---|---|---|
| 时间输入 | 当地公历日期、钟表时刻、有效 UTC 偏移 | 原输入，不依赖运行设备当前时区 |
| 演算时间 | 原时间先换算 UTC 瞬间，再转固定 UTC+08:00 | UTC 瞬间与演算钟表时间并列 |
| 农历历法 | 演算日的现代中国农历 | 农历年、月、日及闰月标记 |
| 年界 | 农历正月初一 | `yearBoundary=lunar-new-year` |
| 日界 | 演算时间 00:00 | `dayBoundary=midnight`；23:00 仍属当日 |
| 时辰 | 23:00–00:59 子，01:00–02:59 丑，依此类推 | 时支和 1–12 序数 |
| 闰月 | 取同名月份数字，如闰六月仍为 6 | `leapMonthPolicy=same-number`，不得丢失“闰”字 |
| 真太阳时 | 首版不校正 | `timeBasis=fixed-utc8` |

固定 UTC+8 是演算基准，不是把历史上海、香港或海外所有钟表时间都当作 UTC+8。输入地过去用 UTC+9 时，应先扣除 9 小时得到瞬间，再加 8 小时演算。夏令时回拨重复时间必须明确选择较早/较晚一次，跳时不存在的时刻应拒绝；手动偏移只能称为用户确认的时间资料，不能称为系统自动完成历史校准。

如首版暂不接 IANA，保留手动偏移即可；页面应提示其必须包含当年夏令时。若接 IANA，应保存解析所得偏移和 UTC 瞬间，恢复历史记录使用保存值，不能每次受设备新版时区库影响而重解。IANA 明确说明数据库记录历史偏移、按地区管理且持续修订，历史资料也不保证权威完备，见[IANA 时区数据说明](https://data.iana.org/time-zones/tz-link.html)。现有手动偏移限定 15 分钟；若要接收 IANA 历史秒级偏移，应另行审查验证规则，不将其偷偷四舍五入。

### 3.3 已核验的库接口

采用 `Solar.fromYmdHms(演算时间各字段).getLunar()`；不要把原始当地时间直接传进去，也不要用依赖设备时区的 `fromDate(new Date())`。

- `getYearZhi()` 或 `getYearZhiIndex() + 1`：普通农历年，以正月初一换年。不要用 `getYearZhiExact()` 或 `getYearZhiIndexExact()`，后者按立春交接时刻换年。[作者干支 API](https://6tail.cn/calendar/lunar.ganzhi.html)
- `getMonth()`：正月到腊月为 1–12，闰月返回负数。先记录 `rawMonth < 0`，再以 `Math.abs(rawMonth)` 作为本版本的月份数。[作者年月日 API](https://6tail.cn/calendar/lunar.ymd.html)
- `getDay()`：农历日数；`getTimeZhi()`：演算钟表时辰。[作者时辰 API](https://6tail.cn/calendar/lunar.time.html)

本次用已安装的 1.8.6 读取以下五组输入，所得年月日与官方表吻合：2025-01-16 15:00、2025-04-13 05:00、2025-01-29 00:00、2025-07-25 00:00、2025-08-23 00:00。此执行是接口核实，不当作独立历法证据。

### 3.4 独立参考案例与测试分层

| 外部出处 | 外部给定参数 | 外部给定结果 | 覆盖内容 |
|---|---|---|---|
| 卷一“观梅占” | 辰年、十二月十七、申时 | 上兑、下离，泽火革；初爻动变咸；互乾、巽 | `5+12+17=34`，加 `9` 为 `43`；下卦动，体兑用离 |
| 卷一“牡丹占” | 巳年、三月十六、卯时 | 上乾、下巽，天风姤；五爻动变鼎；互重乾 | `6+3+16=25`，加 `4` 为 `29`；上卦动，体巽用乾 |

这两行的卦象预期来自[古籍案例原文](https://zh.wikisource.org/zh-hans/梅花易數/卷一)，不是本程序生成的快照。

可结合[香港天文台 2025 年公历农历文字对照表](https://www.hko.gov.hk/tc/gts/time/calendar/text/files/T2025c.txt)做端到端测试：

- 2025-01-16 15:00 UTC+8，对应上一农历辰年十二月十七申时，应复现观梅案例的同组数值。
- 2025-04-13 05:00 UTC+8，对应巳年三月十六卯时，应复现牡丹案例的同组数值。
- 2025-01-29 为正月初一；2025-07-25 为闰六月初一；2025-08-23 为七月初一。用于农历年界、闰月开始与结束测试。

前两组现代日期只是与古籍相同参数的现代测试输入，**不是考证出的古代观梅、牡丹事件公历日期**。香港天文台只证明历日对应，不证明梅花规则或占断。

此外应测：22:59/23:00/00:00/00:59/01:00；同一 UTC 瞬间以不同偏移输入结果相同；跨年与跨日；余数为 0；春节与立春不同日；闰月前后；全部 12 年支×12 时支序数；旧 v1 记录加载/导出结果不变；损坏记录不覆盖；演算时间换算后是否越过支持边界。当前输入年范围为 1900–2099，而 HKO 对照入口覆盖 1901–2100，1900 年尚不能声称已由该表验过。

### 3.5 输入、输出与版本建议

新增独立方法标识 `meihua-calendar`，不复用 `meihua-two-numbers`。结果保留：原输入、UTC 瞬间、固定 UTC+8 演算时间、农历字段、四个取数、两个和数、取余过程、互卦和体用，以及 `calendarEngine=lunar-typescript@1.8.6`、规则版本和上述三项边界约定。

旧记录继续 `divination-v1` 复算；新法用新的可辨识规则版本，未知版本拒绝复算而保留原数据。若未来改为当地民用时、子初换日或不同闰月方案，新增版本或显式方案字段，不能更新后让旧盘结果自行变化。

## 4. 六爻纳甲的装卦规格

### 4.1 数据方向与八宫

数组统一由初爻至上爻。`6=阴动、7=阳静、8=阴静、9=阳动` 保持现状。八宫本宫元素：乾兑金、震巽木、坎水、离火、艮坤土。

八纯卦依序逐变初、二、三、四、五爻，再返变四爻成游魂，最后将内三爻反转成归魂。若初爻为最低位，则相对纯卦 XOR 掩码可用 `[0,1,3,7,15,31,23,16]`。这是算法化表示；生成的 64 卦归属须对照[《增删卜易》八宫全图](https://zh.wikisource.org/wiki/增刪卜易/3/八卦各宮全圖)与第二实现核验。世爻依序 `[6,1,2,3,4,5,4,3]`；应爻与世爻相隔三位。

不能只按上卦、下卦或世爻位置推断卦宫。尤其归魂与三世卦同为世在三，分类顺序错误会污染六亲；`najia` 作者 README 记录过此类修复。[najia 作者仓库](https://github.com/bopo/najia)

### 4.2 纳甲表

内三爻和外三爻分别依所处经卦查表，均自下而上：

| 经卦 | 内卦初、二、三 | 外卦四、五、上 |
|---|---|---|
| 乾 | 甲子、甲寅、甲辰 | 壬午、壬申、壬戌 |
| 兑 | 丁巳、丁卯、丁丑 | 丁亥、丁酉、丁未 |
| 离 | 己卯、己丑、己亥 | 己酉、己未、己巳 |
| 震 | 庚子、庚寅、庚辰 | 庚午、庚申、庚戌 |
| 巽 | 辛丑、辛亥、辛酉 | 辛未、辛巳、辛卯 |
| 坎 | 戊寅、戊辰、戊午 | 戊申、戊戌、戊子 |
| 艮 | 丙辰、丙午、丙申 | 丙戌、丙子、丙寅 |
| 坤 | 乙未、乙巳、乙卯 | 癸丑、癸亥、癸酉 |

地支来自[《增删卜易》浑天甲子章](https://zh.wikisource.org/wiki/增刪卜易/4)，天干另与[najia 固定提交的作者表](https://github.com/bopo/najia/blob/9cf119169d7eb8e48febc05274aebf3f7106d647/najia/const.py)及[ichingpy 固定测试](https://github.com/JinyangWang27/ichingpy/blob/01e50a25d7b1d696ff9c8b9fa5d718a5ca0f63a8/tests/functional/divination/six_lines/test_six_line_divination.py)校核。正文录入存在“辰在内”而非“艮在内”的错字，不机械复制。

地支五行固定：子亥水、寅卯木、巳午火、申酉金、辰戌丑未土。爻五行采用所纳地支的五行，不能取天干五行，也不是六十甲子的纳音五行。

### 4.3 六亲与变卦

以**本卦所属宫五行**为“我”：同我为兄弟、生我为父母、我生为子孙、克我为官鬼、我克为妻财。变爻采用变后经卦的纳甲干支，六亲仍用本卦宫五行。不能用变卦自己所属宫重新定变爻六亲。该原则及“夬变姤”例见[《增删卜易》八宫图章后说明](https://zh.wikisource.org/zh-hans/增刪卜易)。

独立参考：夬卦初爻阳动、上爻阴动变姤；夬属坤宫土，变后初爻丑土、上爻戌土仍标兄弟。它们若把姤当作独立本卦则是父母，因此此案例能直接查出“变卦重定六亲”的错误。界面可画完整变卦，但需区分“变卦结构”与“动爻变出”，避免把静爻也渲染成发生了变化。

### 4.4 伏神

采用“本卦缺某六亲时，从本宫纯卦相同爻位取该六亲”的显示规则；伏神所在的本卦同位爻为飞神。若同一缺亲在本宫纯卦出现多次，应保留所有候选，而不是无依据地只取第一个。首版显示缺亲及各伏藏位置，不自动替用户选择用神。

传统原理和“泰卦无父、父母伏二爻”的案例见[《古今图书集成》该影印页配套转录](https://zh.wikisource.org/wiki/Page:Gujin_Tushu_Jicheng,_Volume_466_(1700-1725).djvu/83)。页面标注“尚未校对”，因此属待影印复核的古籍证据；另有[liuyao-engine 作者固定案例](https://github.com/yaomancy/liuyao-engine/blob/53291663a4c733c4cbdfa174a8d3075475c07fd3/tests/test_feifu.py)：地山谦、财类，二爻伏丁卯木妻财，飞神丙午火。作者用例不是项目自己计算的预期，但也不应宣称等同古籍独立人工审定。

此后可显示飞伏五行生克方向。伏神可否出伏、是否有用属于解释规则，存在取用和流派差异，不由“有伏神”直接推出吉凶。

## 5. 六爻日期事实的后续规格

| 字段 | 建议采用 | 边界 |
|---|---|---|
| 月建 | 以十二“节”的准确交接时刻换月，立春寅、惊蛰卯、清明辰、立夏巳、芒种午、小暑未、立秋申、白露酉、寒露戌、立冬亥、大雪子、小寒丑 | 农历初一不是月建边界；闰月不多一个月建 |
| 日辰 | 按选定演算时间与明确日界取日干支 | 推荐首版与其他本地盘一致为 UTC+8、00:00 换日；这是产品约定，23:00 换日另作版本 |
| 六神 | 依日干自初爻向上循环安置 | 与时干、年干无关；变卦同一问事日不另起六神 |
| 旬空 | 依所选日柱所属十日旬，显示两个空支；爻纳支落在其中可标旬空 | 不直接写“无效”“一定凶”；动空、填空等解释另做 |

作者 API 已明确 `getMonthZhiExact()` 按交节时刻，而 `getMonthZhi()` 按交节当天零点，两者不能混用；`getDayInGanZhiExact()` 将晚子算明天，`getDayInGanZhiExact2()` 将晚子算当天。见[6tail 干支 API](https://6tail.cn/calendar/lunar.ganzhi.html)。选定日界后，日干、日支、六神、旬空必须从同一日柱导出，不能取不同 API 的默认值拼接。

六神循环为青龙→朱雀→勾陈→腾蛇→白虎→玄武。初爻起点：甲乙青龙、丙丁朱雀、戊勾陈、己腾蛇、庚辛白虎、壬癸玄武；以[《增删卜易》六神章的表](https://zh.wikisource.org/zh-hant/增刪卜易/18)与[ichingpy 全十干测试](https://github.com/JinyangWang27/ichingpy/blob/01e50a25d7b1d696ff9c8b9fa5d718a5ca0f63a8/tests/unit/divination/test_six_line_divination.py)互核。古籍转录同页戊子例的排列与表不一致，暂不以该例作为验收真值。玄武/元武、腾蛇/螣蛇/滕蛇仅做名称规范化，不视为不同神。

旬空表：甲子旬戌亥、甲戌旬申酉、甲申旬午未、甲午旬辰巳、甲辰旬寅卯、甲寅旬子丑；见[《增删卜易》旬空章](https://zh.wikisource.org/zh-hant/增刪卜易/26)。必须验证全 60 日干支，包括十日末尾与下一旬开头。日柱输入若提供手动干支，应验证干支确实属于六十甲子，拒绝“甲丑”等奇偶不配组合。

《增删卜易》[月将章](https://zh.wikisource.org/zh-hant/增刪卜易/16)将月将与月建同称；接入其他术数时不能将此术语直接搬到六壬的月将算法。六爻本轮只交付月建事实，不自动混入别的体系。

## 7. 验收门槛

梅花时间法开工前：固定规则名、历法版本、时区和闰月约定；验收至少有古籍两例、HKO 历日边界、同瞬间跨偏移、23/0/1 点、持久化兼容。通过后显示“年月日时起卦”及完整计算过程。
