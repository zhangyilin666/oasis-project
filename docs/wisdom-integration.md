# 传统文化仓库接入：第一阶段

参考仓库：https://github.com/dhicoc/chinese-traditional-wisdom-skill

评估版本：82abcc674bdfb1cee0cf8c33694e8b206a0792f3。

本阶段借鉴“确定性计算 → 结构化字段核对 → 文化解释”的设计，自行实现适配代码。没有复制第三方引擎、古籍、字典或 React 页面，也没有修改 D:/chinese-traditional-wisdom-skill。保留现有 lunar-python 排盘和 Vue/uni-app 手机界面。

## 已实现

- 三个报告 AI 步骤均返回 JSON 契约：text、facts、reference_ids。facts 与本次程序计算的四柱、日主、五行数量、八步大运干支及年龄年份严格比较；缺失字段、数值类型变化、不存在的资料 ID 或无效 JSON 会使步骤失败，报告不能发布为完成状态。
- 对正文中的“年柱/月柱/日柱/时柱：某干支”和“第 X 步大运（干支，年龄区间）”等明确表达额外检查。此规则只覆盖有限句式；结构化字段通过不表示全部自由文本、文化解释或现实预测正确。页面明确说明范围，模拟报告与旧报告不显示核对成功。
- 将生成时提供的最多五个资料片段保存在 report.calendar_data.references 中，附文档 ID、段落位置、内容 SHA-256 和当时的摘录。模型声明使用的 ID 另行保存，不等同于引文真实性认证。旧报告不倒填证据。
- 现有四份资料统一标记为项目学习笔记，包含传统文献摘录和现代解释，未作版本校勘；不以整篇古籍原文名义展示。未导入第三方清单里来源或授权待核验的资料。
- 手机报告提供可展开的资料卡，以及可点击、支持键盘操作的小猫白话词典。词典内容由本项目编写。

## 部署与兼容

所有新数据存储在现有 calendar_data JSON 字段，不需数据库迁移。重新构建后只对新报告启用；失败报告仍沿用现有重试流程。

不新增常驻服务。真实 AI 输出新增结构化字段，会增加 token 开销；每步输出预算增加 2048 tokens。上线前须使用真实配置的提供商完成一次小规模报告验证，不应将模拟测试视作真实模型验收。
