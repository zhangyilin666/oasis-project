# 西方行运：指定日期中午快照

更新：2026-10-03。研究依据与后续模块规划见 [占星接入调研](research/astrology-integration.md)。

## 已实现范围

`calculateWestern(input, options)` 接受可选 `observationDate`。不提供观察日期时，仍只返回现有本命十天体、6° 主要相位与可用的整宫制四轴。提供日期后，在本命结果后增加两节：

- 指定时刻的十天体地心热带黄道位置、顺逆行估算。
- 行运天体对本命天体的合、六合、刑、拱、对冲，统一容许度 **1°**。它是本软件的筛选参数，与本命相位的 6° 分开。

每个日期固定取**北京时间 12:00（UTC+08:00），对应 UTC 04:00**。这是一个时刻的快照，不是该日全部相位；无命中时明确说明“不代表当天没有发生相位”。日期转换不依赖设备时区，也不使用当前时钟自动补观察日期。

沿用共用观察日期校验：合法公历日期，北京时间出生日期至 2099-12-31。出生当天可以选，因此当天中午可能早于实际出生时刻；该约定在结果中明确展示。

## 计算与结果约定

`positions.ts` 统一供本命和行运使用，保留原有 `GeoVector + Ecliptic` 计算方式和前后 1 小时差分估算顺逆行、每日 0.001° 近驻留阈值。没有添加天文依赖，继续使用 MIT 许可 `astronomy-engine@2.1.19`。[引擎官方文档](https://github.com/cosinekitty/astronomy/blob/master/source/js/README.md)、[许可](https://github.com/cosinekitty/astronomy/blob/master/LICENSE)。

`transits.ts` 对十行运行星与十本命天体进行 100 对有方向的比较，包括同名天体回归。行运太阳对本命月亮，与行运月亮对本命太阳，是两种关系。先按未舍入的黄经计算最短圆周距离，再计算与 0°、60°、90°、120°、180° 的误差，误差小于或等于 1° 才纳入。排序依据也是未舍入误差，显示时才取两位小数。

结果保存结构化 `ChartResult.observation`，便于 JSON 导出和历史回放：

```json
{
  "date": "2024-03-20",
  "timeZone": "UTC+08:00",
  "localTime": "12:00",
  "utcTime": "2024-03-20T04:00:00.000Z",
  "kind": "transit-snapshot",
  "orbDegrees": 1,
  "ruleVersion": "western-transit-v1"
}
```

本期比较观察日期与出生日期各自的热带黄经，不做岁差校正。它只计算行星对行星相位，不增加行运四轴、相位精确发生时刻、持续窗口、入相出相与事件预测。地点缺失或处于当前宫位不支持的高纬度，仍可显示地心行运。

月亮的日内变化与出生时间误差均可能改变相位筛选结果；显示到 0.01° 不等于输入或引擎具有该精度保证。

## 独立参考与实测

2026-10-03 从 [Swiss Ephemeris 官方测试页](https://www.astro.com/swisseph/swetest.htm) 的公开服务取得四组、共 40 个黄经参考。公历日期分别为 2000-01-01、2000-08-16、2024-03-20、2026-10-03，均取 UT 04:00；输出报告 `swetest 2.10.03`。完整请求 URL、等价命令、坐标约定及数值保存在 `oasis-uniapp/tests/fixtures/metaphysics-transits.json`。

只保存公开服务输出的数值参考，未嵌入 Swiss 源码、二进制或星历文件。返回没有列出具体星历文件名，因此 fixture 没有依据网站介绍擅自填入 DE441 版本。

本次对照的最大圆周误差为 **0.00447125°（约 16.10 角秒）**，出现在 2026-10-03 的金星。回归门限为 0.02°；它是这四个日期的测试标准，不是对全支持日期的精度承诺。日期黄道、光行差与天文模型的差异仍可能影响最后几位数字。
