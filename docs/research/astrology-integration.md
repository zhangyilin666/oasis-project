# 占星模块接入调研：西方扩展、印度占星、七政四余

检索日期：2026-10-03。本文为实施前研究与建议，不表示下列功能已经上线。

## 结论与当前基础

近期优先接入**指定时刻行运位置与行运对本命相位**；随后是双人比较盘与等宫制。三者可以继续使用现有 MIT 许可的 Astronomy Engine，并由本项目自行实现角度关系，不需要引入新星历依赖。印度占星应先明确岁差量与交点模型，再做 D1、月宿、D9、Vimshottari；七政四余还缺可复现的四余、宿度与宫度规则，应先建立版本化算法规范和参考盘。

已读本地 `docs/metaphysics-houses.md` 与 `oasis-uniapp/src/domain/metaphysics/western.ts`。当前代码使用 `astronomy-engine@2.1.19` 的 `GeoVector + Ecliptic` 计算十天体地心黄经，支持热带黄道、五种主要相位、整宫制与四轴；本命相位统一容许度为 6°。本轮没有运行本地引擎、安装软件、实测新增功能，亦没有复制第三方代码；仅调用公开测试服务取得附录数值。

Astronomy Engine 作者给出的设计精度为约 1 角分，宣称曾对照 NOVAS 与 JPL Horizons；这是上游的声明，不能改写为本项目已经验证的全日期精度。本项目既有六组宫位参考只证明那些样本内的角点误差，不能外推到印度分盘、交点或事件精确时刻。[上游项目说明](https://github.com/cosinekitty/astronomy)、[MIT 许可证](https://github.com/cosinekitty/astronomy/blob/master/LICENSE)。

## 1. 共同数据与计算约定

建议在所有占星结果与快照中记录下列字段，避免表面同名而算法不同：

| 项目 | 必须记录的内容 | 对结果的影响 |
| --- | --- | --- |
| 输入时间 | 原始民用日期时间、历史时区、确认的 UTC、时间精度/不确定范围 | 本命月亮、上升、分盘与达莎起点都依赖它 |
| 地点 | 地理经纬度；需要站心位置时再要求海拔 | 地心行星无需所在地；四轴与宫位需要地点 |
| 位置类型 | 地心/站心、视位置/几何位置、日期黄道/固定历元、时标及引擎版本 | 不同体系数值不能直接当作同一参考 |
| 黄道 | 热带/恒星；恒星模式附岁差量名称、版本、值与模型 | 影响星座、月宿、分盘归属 |
| 宫制 | 整宫、ASC 起算等宫、其他具名规则 | 行星黄经相同仍可能落不同宫 |
| 特殊点 | 交点均值/瞬时模型，远地点均值/瞬时/插值模型 | 不能只存“罗睺”“莉莉丝”等展示名 |
| 观察参数 | 观察时刻、时区、日期输入的默认时刻来源 | 防止将中午快照显示成全天结果 |
| 规则与版本 | 相位角集合、容许度、分盘与达莎规则 ID、参考来源版本 | 允许旧档案复现与新旧规则并存 |

以上为本项目建议的数据契约。天文输入的经度不应再次施加到已正确换算的 UTC 上；需要地方太阳时的传统规则应放在独立规则层，并保留校正前后数值。

## 2. 西方占星扩展

### 2.1 行运最小可交付规格

第一批建议交付名为“指定时刻行运”的结果，范围如下：

1. 输入复用已确认的出生档案，并增加观察日期。若当前界面只能选日期，可复用 `ExplorationOptions.observationDate`，将其定义从“紫微观察日期”改为共用观察日期；西方适配器显式解释为 **该日北京时间 12:00，即 UTC 04:00**。这是本软件的固定取样约定，与出生地时区无关。标题或紧邻说明必须显示完整时刻，不能只写“今日行运”。
2. 结果保存所选日期、固定 `UTC+08:00`、ISO UTC 瞬间，以及“日期输入，固定中午”来源；这里不是历史 IANA `Asia/Shanghai`（历史夏令时的偏移可能不同）。不能使用设备本地时区或运行时当前时钟隐式决定时间。长期应引入 `observationInstant` 或带时区的完整时间对象；仅新增另一个无时区 `transitDate` 并不能消除歧义。
3. 输出十天体的行运星座、原始黄经、显示度数、顺逆行估算；如沿用前后 1 小时差分与近驻留阈值，应与本命盘共同标注为软件计算约定。
4. 比较有方向的“行运天体 X → 本命天体 Y”，十乘十共 100 对；保留同名天体比较，才能显示回归附近的相位。行运太阳对本命月亮不能与行运月亮对本命太阳去重为同一条。
5. 先使用 0°、60°、90°、120°、180° 五类相位，**统一容许度 1°**。这是本产品首版筛选参数，不是所有占星流派通用标准；应与现有本命盘 6° 明确区分。
6. 相位判定使用未舍入角度：`d = min(mod(a-b,360), mod(b-a,360))`；`orb = abs(d-target)`；`orb <= 1°` 纳入。以原始 orb 排序，最后才格式化小数；无匹配时显示空态。
7. 本期不搜索相位精确发生时刻、持续窗口、多次过境或日内全部相位，也不作事件预测。出生地缺失时仍可计算地心行运与行星相位；不增加行运四轴，避免偷偷需要另一个观察地点。

这里采用通常的热带行运比较：观察日期的热带位置与出生日期的热带位置相比较；岁差校正行运是另一种明确命名的方法，不应混入首版。Swiss Ephemeris 一般文档专门区分这两种方法。[官方一般文档，2.8.13](https://www.astro.com/swisseph/swisseph.htm)。

**精度边界：**中午只是快照。月亮在一天内的变化足以改变 1° 筛选结果；出生时间本来只有日期或大致时辰时，本命月亮相位也可能不稳定。界面应保留输入精度提示，而不是通过保留两位小数营造准确感。一个时刻没有命中，不等于当天没有发生过相位。若以后提供“入相/出相”，需定义比较的是误差导数、区分方向与驻留，并用独立时间序列验收。

### 2.2 合盘的范围必须命名

| 功能 | 输入 | 确定性输出 | 近期判断 |
| --- | --- | --- | --- |
| 双人比较盘 Synastry | A/B 各自出生 UTC；宫位叠加需对应地点 | 两套位置、跨盘相位；A 行星落 B 宫及反向 | 可以自研，优先于组合盘 |
| 组合中点盘 Composite | 两套本命盘与明确中点规则 | 两套对应天体/角点的圆周中点 | 暂后；对跖点、中点选择及宫制必须先定义 |
| Davison 时空中点盘 | 两套出生时间、地点及取中点规则 | 中间时间地点对应的实际天象盘 | 独立产品选项，不可与 Composite 共用名称 |

作者对 Composite 的说明明确将其与两人本命的直接比较区分。[Liz Greene 在 Astrodienst 的文章](https://www.astro.com/astrology/in_composit_e.htm?lang=e&pa=nmo)。本项目建议初期只做比较盘，显示相位关系，不给出无出处的“缘分百分比”。任何宫位叠加都使用被落入者的宫位边界，不能因为 A/B 调换后结果不同而视为错误。

### 2.3 多宫制与交点

整宫制以 ASC 所在星座的 0° 起算，ASC 起算等宫制以 ASC 精确度数每隔 30° 分宫；二者都应把 MC 作为独立角点保留。Placidus 涉及昼夜弧划分，极区可能无通常意义的解；上游会在一些失败场景返回其他宫制并报告错误，接入时不能静默把替代盘展示为 Placidus。[宫制与极区说明](https://www.astro.com/swisseph/swephprg.htm)。

建议顺序是整宫 → 自实现 ASC 等宫 → 在参考盘充足后加入一个象限宫制。首期等宫仍沿用现有 `|latitude| < 66°` 产品边界；这只是保守支持范围，不是等宫数学上必然在 66° 失效。

月交点应提供 mean/true 两个明确选项。平均交点是平滑模型，通常所谓真交点由瞬时轨道近似导出；它不是只有一个永远唯一的“真实”数值。平均交点也不是 JPL 星历直接提供的天体。Lahiri 亦有不同版本，名称相同不足以保证同值。[交点、岁差量背景：官方一般文档 2.2 与 2.8](https://www.astro.com/swisseph/swisseph.htm)。

工程建议：交点另开任务，从公开算法/原始理论独立实现或选择许可明确的实现，分别做参考测试；南交点是否严格取北交点加 180° 作为规则固定下来。不要把 Astronomy Engine 的“月亮穿越黄道事件时间搜索”当作任意时刻的平均交点黄经接口。小行星与莉莉丝也不属于现有十天体免费附带能力，不填零值占位。

## 3. 印度占星 Jyotish

### 3.1 最小输入、分层输出与差异

建议首个完整版本输入：出生 UTC、经纬度、时间精度；锁定一种具名岁差量版本、地心视位置、一个交点模型、整宫制与一套分盘规则。保存所用岁差量数值，不能用“热带黄经减去固定 24°”冒充历史日期恒星黄道。

| 层级 | 确定性输出 | 需锁定的规则 |
| --- | --- | --- |
| D1 本命 Rāśi | 日月五行星与 Rahu/Ketu 恒星黄经、星座、上升、整宫位置 | 岁差量、平均/真交点、地心/站心、历元 |
| 月宿 | 27 宿、每宿 4 个 pada、宿内位置 | 27 等分模型与起点；不能混入另有用途的 28 宿表 |
| D9 Navāṃśa | 星座内 9 分区及映射后的星座/度数 | 古典 Parāśara 具名映射、边界归属；分盘不是真实天空的第二张天文盘 |
| D10、D12 等 | 所选分盘的映射结果 | 每种分盘独立规则，不能所有 Dn 都套 `longitude*n` |
| Vimshottari | 出生时剩余大运、后续大运/分运起止 | 出生月宿起算、年长、日期算术、分运顺序 |
| 更高层解释 | 组合、相位、强弱等规则命中 | Parāśara/Jaimini/KP 等具体体系；单独标识来源 |

古典底本可从 Sanskrit Documents 的《Bṛhat Parāśara Horā Śāstra》获取：第 3 章涉及九曜，第 6 章分盘，公开第 46–50 章文本包含达莎规则。它们是研究和交叉校勘入口，不能把转录页无条件当成无误的批校本。[第 1–10 章](https://sanskritdocuments.org/doc_z_misc_sociology_astrology/par0110.html)、[第 46–50 章](https://sanskritdocuments.org/doc_z_misc_sociology_astrology/par4650.html)。

Jagannatha Hora 作者的功能表明确存在多岁差量、地心/站心、平均/真交点、不同日出定义及不同达莎年长：如 365.2425 日、360 日、按太阳角或月相推进计年。因此两个软件的日期不同，首先应比对设置，不能直接宣称某一个算错。[作者功能表](https://www.vedicastrologer.org/jh/features.htm)。

### 3.2 达莎的可测规格

建议仅先实现“出生月亮起算的标准 Vimshottari”，作为具名算法版本。常用九主顺序为 Ketu、Venus、Sun、Moon、Mars、Rahu、Jupiter、Saturn、Mercury，对应 7、20、6、10、7、18、16、19、17 年；总计 120 年。起算不是把出生日起简单排满第一主年数，而是按出生月亮在所在月宿已经走过的比例扣除已用部分。此规则可由古典达莎章与作者教材相互核查；实现前仍需把版本、年长与日期舍入写为固定测试数据。[古典达莎章](https://sanskritdocuments.org/doc_z_misc_sociology_astrology/par4650.html)、[P. V. R. Narasimha Rao 作者公开教材，第 16 章](https://vedicastrologer.org/articles/vedic_astro_textbook.pdf)。

验收建议：月宿起点、终点前后微量、27→1 环绕；九段年数和；出生第一段余额；子运总时长守恒；不把 360 日年与民用 365.2425 日年混算；在出生时间区间两端计算宿与 D9 是否变更。仅出生日期不明时分的资料，不应显示确定的 D9 上升与秒级分运日期。

作者教材是公开可读的有版权作品，作者也说明后来调整过部分规则；公开下载不等于可复制整本译文或代码。[教材首页说明](https://vedicastrologer.org/articles/vedic_astro_textbook.pdf)。Jagannatha Hora 官方页面提供免费使用软件，但本次没有发现允许将程序代码或数据嵌入 MIT 项目的开源授权，故只列为以后人工核对的候选工具，不作为可再分发依赖，也没有在本轮下载安装。[作者官网](https://www.vedicastrologer.org/jh/index.htm)。

印度气象局 Positional Astronomy Centre 发布的 Indian Astronomical Ephemeris 可作为岁差量和恒星位置的进一步官方参考入口，但本次没有取得并逐项核验相应年份的表值，因此不能说已有印度盘参考测试通过。[官方出版物介绍](https://mausam.imd.gov.in/imd_latest/contents/indian_astronomical_ephemeris.php)。

## 4. 七政四余

“七政”可复用日、月、水、金、火、木、土的天文位置；**完整七政四余盘不能只把西方十天体改中文名**。需要额外定义四余、宫度、宿度、立命/身宫以及运限等体系。天文位置准确与古典排盘规则正确是两层验收。

找到可定位的原始文献线索为《图书编》卷二十一“四余总叙”：罗、计与黄白道交点有关且相对；月孛描述与月行迟速有关；紫气与闰余周期有关。文中还包含平行速率与一个古代基准日的躔度。[中国哲学书电子化计划收录文本](https://ctext.org/wiki.pl?chapter=737449&if=gb)。本次读取了搜索索引中的该原文片段，直接打开被站点返回 403；尚未对照影印页，不能把 OCR 数字直接固化进生产算法。另一个维基文库搜索结果与打开正文不一致，已排除作为数值依据。

| 对象/规则 | 候选解释 | 实施前缺口 |
| --- | --- | --- |
| 罗睺、计都 | 月交点的传统命名；现代实现常与南北交点关联 | 明确所选底本首尾方向、平均/瞬时模型、历元；不可跨传统凭名字套值 |
| 月孛 | 与月亮远地点/月行迟速相关的传统参数 | 明确平远地点、瞬时远地点或古历匀速表；不能默认等同西方任一 Lilith |
| 紫气 | 古籍存在与闰余相联系的平行规则 | 缺经校勘的基准日、零点、日率、度量制；不能由“约 28 年”随选现代历元 |
| 二十八宿 | 具名宿界和宿内度 | 固定表还是距星定界、赤道度/黄道度、距星版本及岁差处理 |
| 十二宫与立命 | 传统宫度和立命规则 | 是否恒星/回归基准、太阳时/时辰、顺逆与边界，不能自动等于西方十二宫 |
| 行限与解释 | 依据指定传本的规则 | 原文与现代算法映射、年龄/日期制度、至少一套可复现算例 |

建议把第一期称为“七政天文位置研究表”，仅在研究页提供七政数值与来源；待四余规则完整后才开放“七政四余排盘”。若产品不需要研究页，则继续保持规划状态，避免用伪造的紫气或换名的外行星制造“已经接入”的假象。

上线前最低验收要求：选择一部可查页码的底本和一个现代说明版本；逐条写明符号、周期、基准历元与周天单位；人工复算至少三个不同年代算例；另与一个可配置同规则的软件交叉核验。尚未获得独立参考的四余应输出 unavailable/research，不给确定经度。

## 6. 参考盘与分阶段验收

### 独立参考应分层

- **天体黄经：**优先采集官方 Swiss 测试页的少量可复现数值作 fixture，或 JPL Horizons 的地心视黄经。JPL 的 observer quantity 31 为日期黄道视黄经/纬度，参考配置需保存 `CENTER=500@399`、UTC、目标天体、无大气折射、日期以及返回的星历版本；它采用的 IAU76/80 黄道模型与当前引擎不完全相同，不能要求浮点逐位一致。[JPL 官方手册 quantity 31](https://ssd.jpl.nasa.gov/horizons/manual.html)、[Swiss 官方测试页](https://www.astro.com/swisseph/swetest.htm)。
- **四轴：**沿用本项目已有 `tests/fixtures/metaphysics-houses.json` 六组独立参考；添加等宫时独立计算预期宫头并核验边界。四轴旧 fixture 不包含十天体完整行运真值，不能冒称其覆盖行运。
- **相位关系：**用手算小角度样本验证 359.5°/0.5°、0°/180°、恰好 1°、阈值前后、同名回归、有向跨盘对；这类样本验证角度逻辑，不能代替引擎天文校验。
- **事件时间：**未来若求精确相位，要测试逆行产生多次命中、驻留附近切触、跨 0° 的连续解。根查找“数值收敛到秒”不代表模型和出生输入也精确到秒。
